# FocusFlow 집중 타이머 구현 현황

2026-09-06. 제공된 상세 설계와 화면 흐름을 기존 앱의 디자인 토큰 및 탐색 구조에 통합했다.

## 화면과 기능 연결

- 집중 화면: 측정 방식 → 선택적 작업 연결 → 시작. 바로 시작할 작업은 최대 3개이며 실행 중에는 선택 영역이 숨겨진다.
- 스톱워치: 실제 집중 시간을 누적하며 일시정지 시간은 제외한다.
- 포모도로: 기본 25분 집중, 5분 짧은 휴식, 4회마다 15분 긴 휴식. 휴식 자동 시작과 다음 집중 자동 시작은 별도 설정이다. 휴식은 작업 실적에 포함하지 않는다.
- 종료 결과: 기록을 저장하고 메모, 작업 사후 연결, 다시 시작을 제공한다. 작업 완료 처리는 별도 선택이다.
- 기록: 기간과 작업/미지정 필터, 집중 구간 기준 통계, 메모, 작업 재연결, 삭제를 제공한다. 연결 변경과 삭제는 작업의 누적 실적도 조정한다.
- 몰입 보기, 전역 표시, 웹 미니 창, Tauri 미니 창/트레이는 공통 세션 명령을 사용한다.

## 상태 및 데이터

`src/domain/focus/engine.ts`가 시작·일시정지·재개·종료·휴식 전환과 실적 변경을 계산한다. `usePlannerData`는 저장 성공 이후 상태를 확정한다. 같은 출처의 여러 탭은 Web Lock과 BroadcastChannel로 호스트를 공유한다.

10초 체크포인트를 저장하며 재실행 시 마지막으로 확인된 시간까지 복구하고 일시정지한다. 저장 공백은 사용자 확인 후 추가할 수 있다. 긴 콜백 공백과 시계 변동은 보수적으로 처리하며 실제 OS 절전 감지 API를 사용하지는 않는다.

저장 실패 시 세션을 보류하고 재시도하며 완료 시간을 중복 가산하지 않는다. 기존 데이터는 최초 v2 저장 전 `focusflow.focus.v2.backup` 로컬 저장소 키에 백업한다. 과거 구간 정보가 없는 기록에는 임의의 집중 구간을 생성하지 않는다.

## 검증 및 배포 경계

- TypeScript 검사 및 production build 통과.
- Rust `cargo check` 통과.
- 신규 브라우저 시나리오: desktop 8개, tablet 8개, mobile 8개 통과.
- 기존 작업 상세 브라우저 시나리오 desktop 2개 통과.
- 전체 단위 테스트: 2,715개 통과, 1개 건너뜀, 기존 색상 토큰 불일치 1개 실패 (`itemColor.tokens.test.ts`, `#68686d` / `#8e8e93`). 해당 팔레트 및 CSS 토큰 파일은 이번 작업에서 변경하지 않았다.
- 실제 Tauri 패키지 실행, Windows 트레이/절전 복귀, 로그인한 다중 기기 동기화는 실환경 검증이 남아 있다.
- `supabase/migrations/018_focus_v2_writer_guard.sql`은 작성만 했으며 서버에 적용하지 않았다. 새 클라이언트 배포 후 적용해야 한다. v2 기록이 있는 계정의 구버전 클라이언트 쓰기를 제한하므로 서버 배포 시 별도 검증이 필요하다.

원본 이미지의 장식 배경과 별도 사이드바를 그대로 복제하지 않고 기존 앱 탐색 구조와 디자인 토큰을 사용했다.
