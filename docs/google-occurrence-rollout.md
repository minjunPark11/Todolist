# 반복 회차 전송(M6) 적용과 검증

## 현재 상태

회차 수정·이동은 해당 인스턴스에 조건부 PATCH, 건너뛰기는 DELETE로 전송한다.
새 이벤트 생성이나 원본 반복 규칙 수정은 이 경로에서 하지 않는다.
037은 `occurrence_sync_enabled=false`로 설치된다. 운영 DB 적용 상태와 테스트 계정이
확인되지 않았으므로 이번 작업에서 운영 활성화·실제 Google 쓰기는 실행하지 않았다.

2026-09-10 로컬 검증: 관련 테스트 172개 및 프로덕션 빌드 통과.
PGlite에서 021–036 뒤에 037을 적용해 기존 시간대 재설정 테스트도 통과했다.
이는 운영 PostgreSQL 동시 접속이나 Google 실계정 검증을 대체하지 않는다.

## 1. 운영 선행 조건

1. `supabase/ops/state.sql`, `028_034_verify.sql`, `activation_status.sql`로 실제 상태를 읽는다.
   문서의 과거 적용 기록은 현재 운영 상태의 증거로 대신하지 않는다.
2. 007 및 021–036의 적용, 정확히 하나의 활성 Inbox, 검증된 전용 캘린더,
   프로토콜 2 전환 및 기존 토큰 소진, 테스트 계정의 작업 동기화 활성화를 확인한다.
3. 기존 동기화로 일반 작업 생성·수정·삭제가 되는지 테스트 계정에서 확인한다.

## 2. 구현 배포

검증 환경에서 037을 적용하고 `037_occurrence_verify.sql`을 실행한다.
서버 `/api/google/task-write`와 클라이언트를 함께 배포한다. DB가 먼저이며,
마이그레이션 적용만으로 새 전송을 켜지 않는다.
명시적으로 선정한 테스트 계정만 DB 소유자가 `occurrence_sync_enabled`를 켠다.
이 플래그는 일반 사용자가 변경할 수 없다. 실계정 검증을 통과하기 전 전체 계정에 켜지 않는다.

## 3. 전송과 복구 계약

- 주소는 현재 세대의 검증된 원본 매핑과 **원래 시작 시각**으로 구한다.
  `googleEventId`가 복사된 로컬 행을 소유권 증거로 쓰지 않는다.
- `events.instances?originalStart=...`로 이미 다른 날짜로 옮긴 회차도 조회한다.
  종일은 날짜, 시간 일정은 연결 시간대에서 계산한 실제 시각을 사용한다.
  DST 중복·누락 시각은 추측해서 전송하지 않는다.
- 기존의 lease/fence, 작업 revision, 서버 예약, OAuth 차단을 공유한다.
  전송 직전 원본 및 회차 revision과 연결을 다시 확인한다.
- 결과가 불확실하면 전송을 반복하지 않는다. GET으로 변경된 etag 또는 취소 상태를
  확인한 뒤 완료/중단한다. 응답이 유실된 DB 완료 기록만 같은 요청으로 재시도한다.
- 성공한 회차의 기준 내용과 취소 기록은 별도로 보관한다. 다음 패스에서 같은 변경을
  다시 보내지 않으며, 원본 매핑의 기준 내용을 회차 내용으로 바꾸지 않는다.
- Google에서 같은 회차가 변경되었으면 자동 덮어쓰기를 중단하고 설정에 제목·회차 날짜를
  안내한다. 회차 충돌의 양쪽 선택 UI는 이 변경의 범위 밖이다.

## 4. 실계정 수락 검증 — 아직 실행하지 않음

전용 테스트 계정에서 식별 가능한 테스트용 주간 반복 작업을 사용한다.

| 순서 | 동작 | 통과 조건 |
|---|---|---|
| 1 | 시간 일정에서 다음 회차만 하루 이동 | Google의 해당 회차만 이동, 원본과 나머지 회차 유지 |
| 2 | 이미 이동한 회차의 제목·메모·시각을 다시 수정 | 같은 인스턴스 ID 수정, 별도 이벤트 생성 없음 |
| 3 | 다른 회차 건너뛰기 | 해당 회차만 취소 |
| 4 | 같은 동기화를 두 번 실행하고 앱 재시작 | 추가 PATCH/DELETE나 중복 이벤트 없음 |
| 5 | 종일 반복, 여러 날 종일 반복, DST 전후 일정 | 원래 시작 날짜/시각의 인스턴스에만 반영 |
| 6 | Google에서 먼저 같은 회차 수정 | 앱의 자동 덮어쓰기 중단 및 회차 안내 |
| 7 | 테스트 환경에서 401·412·429, 전송 성공 후 응답 유실 주입 | 명시적 거절은 새 예약, 불확실한 쓰기는 GET 복구만 수행 |
| 8 | 대기 중 다른 기기 편집 및 계정 전환 | 오래된 revision/연결로 전송하지 않음 |

검증 결과에는 테스트 계정 식별자, 앱/서버 커밋, 적용 migration, 시각, 원본/회차 ID,
예상 결과와 실제 결과를 기록한다. 토큰·비밀키는 기록하지 않는다.
테스트 데이터 정리는 테스트용으로 만든 작업에 한정한다.

원격 취소의 404/410만으로는 성공을 단정하지 않는다. 조회가 계속 불확실하면 기존
`recover_google_task_no_write` 운영 절차를 따른다. 플래그를 끄더라도 진행 중 예약을 지우지 않는다.

Google API 근거: [instances](https://developers.google.com/workspace/calendar/api/v3/reference/events/instances).
